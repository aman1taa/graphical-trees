Бинарный поиск символа

Три типа двоичного поиска в отсортированном массиве. Тип 1 ищет точное вхождение символа, тип 2 — позицию вставки (lower bound), тип 3 — сразу все вхождения символа. На каждом шаге видно, как сужается диапазон.

Если набор введён не по порядку, он будет отсортирован автоматически. Повторы сохраняются.
Чем отличаются три типа

Тип 1. Проверяем средний элемент. Если он равен искомому — ответ найден. Если искомый меньше, продолжаем в левой половине, иначе — в правой. Когда lo > hi, элемента в массиве нет.

Тип 2. Ищем не сам элемент, а границу: первое место pos, где a[pos] ≥ x. Такой поиск возвращает позицию вставки, сохраняющую порядок, и корректно работает с повторами. Если x больше всех элементов, ответ — n (вставка в конец).

Тип 3. Ищем все вхождения символа. В отсортированном массиве равные элементы стоят подряд, поэтому достаточно найти нижнюю границу (первое a[i] ≥ x) и верхнюю (первое a[i] > x) — все позиции между ними и есть ответ.

// Тип 1: точное вхождение
lo = 0; hi = n - 1;
while (lo <= hi) {
  mid = (lo + hi) / 2;
  if (a[mid] == x) return mid;
  if (a[mid] < x) lo = mid + 1;
  else hi = mid - 1;
}
return -1;

// Тип 2: lower bound
lo = 0; hi = n;
while (lo < hi) {
  mid = (lo + hi) / 2;
  if (a[mid] < x) lo = mid + 1;
  else hi = mid;
}
return lo;

// Тип 3: все вхождения
lo = 0; hi = n;
while (lo < hi) {                  // нижняя граница
  mid = (lo + hi) / 2;
  if (a[mid] < x) lo = mid + 1;
  else hi = mid;
}
first = lo;
lo = 0; hi = n;
while (lo < hi) {                  // верхняя граница
  mid = (lo + hi) / 2;
  if (a[mid] <= x) lo = mid + 1;
  else hi = mid;
}
last = lo - 1;                     // вхождения: a[first..last]
Почему поиск занимает O(log n)

После каждого сравнения остаётся не более половины текущего диапазона. Количество шагов не превышает ⌈log₂(n + 1)⌉, поэтому для 1000 элементов достаточно около 10 сравнений. Массив должен быть отсортирован — иначе отсечение половины не работает.
